1. Always prefer using bun.js over using npm or Node.js for typescript, javascript project
2. Always try to understand what the project is about and read PROJECT_DESCRIPTION.md
3. Important: Write this file as if you were writing for an AI agent who doesn't know anything about the project, so they can contribute
4. After each task, you will need to update the PROJECT_DESCRIPTION.md file to update the context of the project, like
   - [ ] what task each file handles
   - [ ] how the flow of the feature works
   - [ ] what function or what file is responsible for something
   - [ ] how something works
   - [ ] what needs to be updated in the future, or new ideas
   - [ ] the note of feature like warning or notice or etc,...
   - [ ] summarization of walkthrough.md
   In case the project description is not found, you will create the new one and fill it with things that you know
   NOTE: Some of the project note maybe missing some information, so you are responsible to update that for fit with current project
5. In some quite big tasks, you can create the plan.md with the detailed plan and track when each task is done
6. Use type validation after each task for checking when you don't have a check, and also avoid using type any
7. For React.js (or some frontend project, subproject like that), please try to reuse as many components as possible (include detecting duplicate code and creating a component for that) (*dose the same with function)
8. After each task, you will need to update the changes.md (with header time before adding change)
